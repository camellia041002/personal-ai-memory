# 从 V1 到 V8

## 先分清两组版本

- **Lite 和 V8**：现在真正可以选择部署的两个版本。Lite 面向第一次使用的人；V8 面向需要更强检索和恢复能力的人。
- **V1 和 V8**：项目历史上的起点与终点，用来说明它如何演进。V1 存在明显安全缺陷，源码没有公开，也不是当前基础版或可部署版本。

项目最初只是一个使用 Worker 和 KV 的简单原型。在持续使用和迭代中，项目逐步处理了分页遗漏、检索不准、索引失败、误覆盖风险和权限过宽等问题，加入日记规则、语义检索、重叠切片、索引状态和恢复机制，最终演进到 Hybrid V8。

## MCP 工具变化

| 工具 | V1 | V8 | 作用与变化 |
| --- | --- | --- | --- |
| `save_memory` | 有 | 有 | 按 key 保存记忆；V8 同时维护检索索引 |
| `get_memory` | 有 | 有 | 使用完整 key 读取一条记忆 |
| `list_memories` | 有 | 移除 | V1 可直接列出 key；V8 改为受限查找，避免无条件枚举 |
| `get_all_memories` | 有 | 移除 | V1 可批量读取正文；V8 为缩小权限而取消 |
| `delete_memory` | 有 | 有 | V1 直接删除；V8 要求 `confirmKey` 与目标 key 完全一致 |
| `save_daily` | 无 | 有 | 按日期和 owner 保存日记，发生冲突时要求明确覆盖 |
| `find_memory_keys` | 无 | 有 | 按关键词、前缀、分类等筛选少量 key，最多返回 20 条 |
| `get_recent_dailies` | 无 | 有 | 读取限定天数内的近期日记 |
| `search_memories` | 无 | 有 | 合并精确短语和语义检索，返回最相关的记忆片段 |

V8 另有三个管理员能力：分页查看 key、检查索引状态、逐 key 重建索引。它们由单独的 `ADMIN_TOKEN` 保护，不属于普通 AI 可以调用的 MCP 工具。

## 用户能感受到的五次升级

1. **从记住名字到按意思查找。** Lite 和早期版本更依赖完整 key；V8 可以按正文含义和精确短语搜索。
2. **从整篇保存到分段检索。** V8 使用重叠切片，让长记忆中的相关段落更容易被找到。
3. **把日记当成专门的数据类型。** 可以按日期与 owner 保存，并读取限定范围内的近期日记。
4. **索引故障不等于原文丢失。** 保存时优先保住 KV 原文；索引失败会留下状态，管理员之后可以检查并修复。
5. **普通工具与管理权限分开。** V8 取消无条件全量读取，限制查找数量，删除要求二次确认，并把恢复能力放在管理员接口中。

V8 默认以 650 个字符为切片目标，单个切片最长 850 个字符，相邻切片重叠约 100 个字符。这里的“字符”按 JavaScript 字符串长度计算：普通汉字通常按 1 个字符计，英文字母、数字、标点和空格也会计入；部分 emoji 可能按 2 个字符计。因此，650 是切片长度目标，不等同于严格的 650 个汉字。

## 关于覆盖

`save_memory` 使用相同 key 保存时，会替换原有内容。Lite 没有版本历史或撤销功能；重要内容建议使用新 key 保留旧版本，或另行备份。V8 增加了索引状态与恢复机制，但这不等于记忆正文的版本管理。
